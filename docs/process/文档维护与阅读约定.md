# 文档维护与阅读约定

## 文档如何分工

论文笔记回答“作者为什么做、具体怎么做、实验支持什么”。综述比较多个研究问题与设计，不逐篇复制摘要。赛题文档只记录规则、来源和版本。研究文档记录我们的假设、选择和待验证问题。实验记录只写实际执行的配置与观测。

主要正文直接编辑Markdown。已有HTML、Canvas、JSON及CSV保留作历史快照或数据附件；不让生成脚本覆盖后续人工修改的Markdown。

## 每篇论文的阅读要求

1. 明确作者试图解决的具体问题，并区分问题陈述与已证明事实。
2. 定义输入、输出和基本张量维度。
3. 沿前向计算顺序解释模块：输入从哪里来、输出送到哪里、为何需要这一转换。
4. 单独解释位置表示、时间/空间轴、mask和读出。
5. 写明每阶段训练对象、损失、冻结参数和外部权重。
6. 把主要结论定位到实验表、图或消融，并保留协议条件。
7. 记录局限、未读懂的部分、代码与论文的潜在差异。
8. 最后才讨论本项目可以借鉴什么；借鉴意见必须可由实验否定。

如果需要“详细架构”，仅写模块名称和框图不算完成。应能沿着笔记解释一次前向计算。精确参数未核验时应明确缺口，避免用常见实现替作者补齐。

## 符号

$B$：batch大小；$C$：通道数；$T$：原始采样点数；$N$：时间patch/token数；$D$：表示维度。各论文符号可能不同，笔记会转换为这些记号；转换后的示意公式不冒充论文原编号公式。

## 证据与版本

- 记录所读论文版本以及对应原文链接。
- 作者报告结果、独立benchmark结果、我们的实测分别注明。
- 不用跨协议的数值差异证明架构优劣；不把整模型排名解释成单模块因果。
- “论文已读”“代码已核对”“运行成功”“指标复现”分别更新。当前多数笔记处于论文阅读初稿，不能写成已经复现。
- 有新的比赛通知时更新赛题正文，并在决策记录中留下变更来源与影响。
