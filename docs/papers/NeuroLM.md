# NeuroLM：研究问题、架构与训练逻辑

> 版本：2026-11-13 / 论文笔记 v0.1。正文基于已保存原文及公开评测；尚未完成代码逐层核验或本地复现。统一记号见[阅读约定](../process/文档维护与阅读约定.md)。

## 研究出发点

作者希望让同一模型通过指令完成多种EEG任务，减少每个任务独立设计和微调的需求。关键研究问题是如何把连续神经信号转换为语言模型可以共同处理的token。

## 从输入到输出的架构

流程分三个阶段。

1. **神经tokenizer：**将每通道EEG patch编码为潜在向量，再通过VQ codebook量化。时域与频域预测提供信号监督，域对齐使神经表示与文本表征更接近。
2. **多通道自回归：**固定已训练的tokenizer，将神经token送入语言模型式骨干。序列组织需要处理同一时刻的多个通道，不可直接把任意通道拼接顺序当作真实时间因果。
3. **指令微调：**把EEG token与任务描述、指令及答案token组织成输入输出序列，优化答案的条件生成。

生成目标可以概括为 $-\sum_i\log p(y_i\mid EEG,instruction,y_{<i})$。这个系统的最终输出是离散文本/标签token，不是普通encoder后接单个softmax头。

## 训练目标与阶段

Tokenizer学习、脑信号自回归学习、任务指令学习分别有不同的训练对象。评价时要记录LLM初始化、文本语料、神经tokenizer是否冻结及各阶段数据。若借鉴共享任务表示，需要独立检验语言生成层的收益，不能将多任务数据或额外语言先验带来的变化全部归给EEG骨干。

## 实验告诉了我们什么

原论文是多任务系统比较，不构成对REVE的统一优势证据；UniMind同表进一步显示多任务设计仍有明显改进空间。

这些结果的协议和具体源表见[评测证据](../benchmarks/评测证据与可比性.md)。整模型优于另一模型，只能支持该完整设置下的比较；模块作用需要相应消融。

## 局限和仍需核对的问题

语言模型、tokenizer、指令数据引入多重变量；决赛禁止加载任何预训练权重，也涵盖冻结的外部预训练LLM。

实现核对时重点记录：预处理、实际token形状、位置表示、mask与loss的作用位置、checkpoint版本、可训练模块及读出接口。没有核验到的层数、配置或实现差异不补成确定事实。
